# Using the panel

- **Working:** every thread T3 reports as running, waiting, queued or starting, plus a thread whose agent ended its turn but is waiting on a background task (`t3_background_wait`). T3 reports that last kind as `completed`, so the app infers it from the run's items. The same goes for a thread waiting on its own subagents (delegated tasks): while one is still working, the parent shows "Waiting on a subagent" instead of Done. This is a guess from item patterns, not an official T3 signal. A background-task wait expires after 2 hours; a subagent wait lasts as long as the subagent works.
- **Done:** a thread stays listed after it finishes, and any unsettled thread that finished in the last 30 minutes is added even if the app never saw it run.
- **Row info line (replaces the old progress bar, which had no real total to show):** step count · run time · model icon · project. The icon follows the model name first (Claude, OpenAI, Grok, Qwen and so on) and the provider second; hover shows the exact model and provider. The detail view lists project, branch, run time, run number and model, and adds "ran on …" when the run executed on a different model than the thread's. T3 reports no executed model for some providers (pi), which is shown as nothing, not as a difference.
- **Secret requests:** when an agent asks for a secret (T3's `request_secret`), the row says "asks for a secret" with the label and an **Enter it in T3 Code** button. The value is only ever entered in T3; Agent Huddle has no field for it and never holds one.
- **Machine headers:** threads are grouped by machine. A header says **Linked only** (read-only: connect the machine to answer), **Offline** (signed in, not answering; its last list stays greyed for a short while) or **Sign-in expired**.
- **Questions:** pick an option and **Send**, or **Write answer** to answer in your own words (⌘↩ sends, Esc goes back). A question the panel cannot show (several questions, multi-select) says to answer it in T3 Code; the row's ↗ opens it.
- **Message a thread:** the speech-bubble button on a row opens a small composer under it; the detail view has one at the bottom. The button says what will happen: **Send** (the thread is not running, so a new turn starts), or **Queue** (sent after the current turn). While a turn is running, the ⇄ part of the button flips it to **Steer** (orange): the message reaches the agent during this turn. ⌘↩ sends, ⌥⌘↩ steers once, Esc cancels. Before a steer the app checks that the turn is still running; if it ended, nothing is sent and the composer asks whether to send it as a new turn. The ⤢ in the field opens a bigger editor window for long text. Drafts stay in memory (not on disk) until sent or the app quits. Read-only mode sends nothing. A thread that is asking you something (question, permission, secret) gets that first, so it has no message button, and neither does a thread from a machine that is only linked (T3 refuses those sends; connect the machine in Machines… to get one).
- **Steps:** every step is expandable. A running step is open until you close it; finished steps start closed. A command opens to its output (last 20 lines), other steps to the start of their input. T3 exposes no token or context-window numbers, so none are shown.
- **Panel size:** drag the panel's bottom edge to set the tallest it may get (default 640 pt, remembered). It still shrinks to fit when there is less to show, and the list or steps scroll when there is more. The width is fixed.
- **Start a thread:** the **+** next to the title (⌘N) opens a composer: pick the machine and project, type the task, **Start**. **Options** sets the model, mode (Approval, Accept edits, Auto), workspace (project checkout or a new worktree), plan first and the title. Defaults are in **Settings → General → New threads**. Only machines you are connected to are offered.
- **Something needs you:** the menu-bar robot shows an orange count of threads that ask a question, need permission or ask for a secret, and the count beside the panel's title turns into the same orange badge: click it to jump to the first one (also when the panel is collapsed, and in a thread's detail). In **Settings… → General**, "Show the panel when something needs me" brings a hidden panel back for a new request (off by default).
- **Settings:** menu bar → **Settings…** (⌘,): General (attention, chime, read-only mode, close also settles, keep the window on top) and Machines (each machine's **Connected** sign-in and **Approve commands from the panel**, set up in place). The window stays on top while open.
- **Close (×):** hides a thread. It comes back by itself when it starts working again (a new run), asks a question or needs permission. If "Close also settles" is on, closing a finished thread settles it in T3 instead.
